# Codex 工作台知识迁移与治理经验

本笔记提炼自旧 `D:\Codex` 工作台的根规则、结构文档、项目模板和迁移实践。路径专属配置已舍弃，只保留可复用方法。

## 1. 按知识生命周期组织，而不是按 Agent 名称组织

稳定结构应回答“这份内容处于什么阶段”：

```text
原始输入 → 过程提取 → 可复用知识 → 案例 / 交付 → 经验回写
```

在本库中的映射：

- 原始输入：`00.raw-materials/00.inbox`、`10.sources`
- OCR、提取、整理：`00.raw-materials/90.processed`
- 专题知识与持续工作：`30.areas`
- 自动化与构建：`00.raw-materials/99.system`

## 2. 原始证据、知识和交付物分开

- 原图、Word、PPT 是 Evidence，不应被改写稿替代。
- 结构化笔记用于理解和检索，不等同于正式系统事实。
- 当前有效版本必须有明确入口，旧版本不应与当前版本并列展示。
- 交付物版本落后于 Markdown 时，应显式标注两个版本，避免误用。

## 3. 用轻量索引控制上下文

复杂专题至少维护：

- `README.md`：范围、边界、内容地图。
- `Dashboard.md`：高频任务和当前入口。
- 迁移 / 版本清单：来源、取舍、当前版本。

Agent 先读索引，再按任务读取少量相关文件。不要把整个知识库一次性装入上下文。

## 4. 经验回写形成闭环

一次需求完成后：

1. 正式稿进入案例区。
2. 新确认的业务规则回写专题逻辑。
3. 重复出现的写作问题回写 SOP / Prompt。
4. 遗漏项回写 Review Checklist。
5. 可测试规则转为 TestCase。
6. 关键结论补 Evidence 链接。

## 5. 安全迁移顺序

```text
盘点 → 内容哈希去重 → 目标映射 → 精选复制
→ 修复路径 → 建立索引 → 完整性验证 → 再处理旧位置
```

删除旧位置前必须确认：

- 目标文件存在且哈希一致；
- 旧绝对路径已清除；
- 当前版本入口明确；
- 目标库已有用户修改未被覆盖；
- 被排除内容确实是缓存、工具、旧稿或空占位。

## 6. 本次迁移的实际启发

- 大体积不等于高价值：源工作台主要体积来自工具程序、临时渲染和图片。
- 文件名不同不代表内容不同：DSP PPT 在目标库中已重命名，但 SHA-256 完全一致。
- “全部搬走”会把旧路径、本机配置和大量草稿带入新库；迁移应保留证据与知识完整性，而不是保留目录噪声。
- 对需求单类知识，最重要的是当前版本矩阵、原始证据、确认记录和可复用检查清单。
