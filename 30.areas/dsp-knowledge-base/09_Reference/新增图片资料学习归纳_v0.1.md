## 1. WPHLoss

资料路径：`00.raw-materials/10.sources/images/WPHLoss/`

已沉淀到：`02_Logic\WPHLoss.md`

核心理解：

- WPHLoss 用于修正复合机台因 chamber 缺失造成的实际 WPH 损失。
- 判断是否启用 WPHLoss 时，按 `Lot / stepseq / EQPID` 分组。
- 同组 STN 需要有相同且非空的 `ProcessGroup`，并且 `WPHLossControl = Y`。
- `chamberflow` 先按 `;` 拆不同 PPID，再按 `,` 拆 chamber，并去重。
- 根据 `SubeqpStateGroup` 统计缺失 chamber 数：

```text
CountGap = SameGroupCount - ActualCount
```

- 按 `Capability / ProcessGroup / Machine / SubeqpStateGroup / Count` 匹配 Loss。
- 多个 chamber group 时，最终 WPHLoss 取最大 Loss。
- 实际 WPH：

```text
Actual STN WPH = Total STN WPH × (1 - WPHLoss)
```

- 若 WPH 按 chamber 维护，还需按 chamber ratio 分摊修正后的实际 WPH。

## 2. PM Control / PM 提前回线判断

资料路径：`00.raw-materials/10.sources/images/PM_Control/`

已沉淀到：`02_Logic\PM_Control.md`

核心理解：

- 原逻辑主要用 `Qsort > PM Start` 判断 PM 管控，长 Loop 可能管控过早。
- 现逻辑中，PM 管控判断的到站时间使用 CycleTime 累计，替代原逻辑的 Qsort。
- 新逻辑同时引入 `PMQzoneControl`、PM Start / PM End 修正、PM buffer / Ratio 等判断。
- `STNPMTimeControl` 维护：
  - Machine
  - Min / Max PM Time
  - PM Start Ratio
  - PM End Ratio
  - Mon Ratio
  - Time Control
  - Start / End Time
- 当 `PMQzoneControl = Y` 时：

```text
PMStartTime = PlanStartTime - PMTimeDuration × PMStartRatio
PMEndTime   = PlanEndTime + PMTimeDuration × PMEndRatio + (StdMonPM + PirunStdTime) × (1 + MonRatio)
```

- PM / 借机处理方式不同，不能套同一公式。
- MFG Prefer / 断线对厂机台选择时，也要判断对厂机台是否在 PM 管控区间。
- Merge Lot / 子母批要按 Group 联动判断，避免部分 Lot 通过、Merge 后卡住。
- PM delay report 需要避免同 Lot 同站点多机台重复计算延期时长。

用户已确认：图片中的字段实际为 `$End`，表示当前时间；`PMStartTime = PlanStartTime - $End`、`PMEndTime = PlanEndTime - $End` 表示转换为相对当前时间的剩余时间。

用户已确认：PM 管控判断中，Lot 到站时间使用 CycleTime 累计，替代原逻辑中的 Qsort。

## 3. Qsort

资料路径：`00.raw-materials/10.sources/images/Qsort/`

已沉淀到：`02_Logic\Qsort.md`

核心理解：

- Qsort 是 Lot 到计算站点的最大允许等待时间。
- Qsort category 固定为：

```text
0 / 6 / 12 / 24
```

- 用户补充确认：WaferBalance 中说的 Qsort 都是 Existing qsort，不是 Virtual Lot qsort。

- 当前站点 PT 按片数和 capability。
- 其余站点 PT 按 recipe，不按片数。
- Virtual Lot：

```text
Qsort = A - B
```

- Existing Lot 多数场景：

```text
Qsort = MAX(A, B)
```

- Existing Lot 当前状态为 `WaitForJobIn` / `JobOut`，且当前站点为 QTime 结束站时：

```text
当前站点 E_Qsort = 0
```

## 4. TestCase SOP

资料路径：`00.raw-materials/10.sources/images/TestCase_SOP/`

已沉淀到：`01_SOP\TestCase_SOP.md`

核心理解：

- 写 TestCase 前先列功能涉及清单：
  - 厂别
  - Macro
  - Report
  - 功能模块
  - AMA Rule
  - 接口
- 公司测试用例模板字段包括：
  - `No`
  - `所属(Local/Central)`
  - `Area`
  - `涉及 Macro / 共通模块`
  - `逻辑变动内容`
  - `类别`
  - `测试内容`
  - `测试情景`
  - `预期结果`
  - `测试结果`
  - `测试日期`
  - `测试 owner`
- 测试不应只写“功能正常”，而要拆成正向、反向、特殊符号、边界、数据处理、Branch 交互、MultiLot、厂别、CrossFab、产品客制化、联动、性能等维度。

## 5. 对后续需求单的影响

以后写 DSP 需求时：

- 涉及 QZone / Loading / WaferBalance 时，需先确认是否要使用修正后的 WPHLoss WPH。
- 涉及 PM / 借机 / 对厂 / Prefer 时，必须读取 `PM_Control.md`。
- 涉及 WaferBalance 的 qsort category 或 QTime 放货判断时，必须读取 `Qsort.md`，且按 Existing qsort 理解。
- 需求完成后生成 TestCase 时，必须按 `TestCase_SOP.md` 的涉及清单和测试大类检查覆盖度。
