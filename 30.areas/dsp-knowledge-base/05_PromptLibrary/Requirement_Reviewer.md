# Requirement Reviewer Prompt

> 用途：Review 需求单是否完整、是否符合 SOP、是否能支持 IT 开发和测试。

## 输入

```text
待 Review 需求单：
涉及系统：
重点关注：
已知未确认事项：
```

## Review 顺序

1. SOP 格式检查
2. 业务目标检查
3. 原逻辑 / 新逻辑完整性检查
4. 数据来源 / 字段 / 获取条件检查
5. 判断逻辑检查
6. 输出结果检查
7. 异常 / 边界 / 空值处理检查
8. RTD / AMA / MES / MCS / EAP 影响检查
9. Report / UI / Rule / DB 影响检查
10. 是否具备后续单独生成 Test Case Excel 的条件；不要求需求单包含 Test Case 明细

## 输出格式

| 等级 | 问题 | 影响 | 建议修改 |
| --- | --- | --- | --- |
| P0 / P1 / P2 |  |  |  |

等级说明：

- P0：会导致需求无法开发、逻辑错误或上线风险高。
- P1：会导致 IT / 测试追问，或边界场景不清。
- P2：表达、格式、可读性优化。

## 必查问题

- 是否明确唯一维度。
- 是否明确字段含义。
- 是否明确空值 / 缺失值处理。
- 是否明确是否复用现有逻辑。
- 是否明确新增逻辑和旧逻辑的边界。
- 是否有“看似自然语言但不可开发”的描述。
