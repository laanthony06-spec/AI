# Requirement Review Checklist v1.1

> 用途：Review DSP 需求单是否可开发、可测试、可上线。

## 1. SOP 与结构

- [ ] 是否包含基础信息。
- [ ] 是否说明项目背景、存在问题、需求目标。
- [ ] 是否有原逻辑 / 现逻辑 / 修改原因。
- [ ] 是否有流程图。
- [ ] 是否有待确认事项。
- [ ] 是否有审批意见区。

## 2. 数据来源

- [ ] 表名是否明确。
- [ ] 字段名是否明确。
- [ ] 字段含义是否明确。
- [ ] 获取条件是否明确。
- [ ] 获取范围是否明确（FAB6 / FAB8 / 单厂 / 两厂）。
- [ ] 字段缺失时的处理是否明确。

## 3. 逻辑完整性

- [ ] 输入是什么。
- [ ] 判断条件是什么。
- [ ] 处理动作是什么。
- [ ] 输出结果是什么。
- [ ] 是否定义唯一维度。
- [ ] 是否说明重复记录如何处理。
- [ ] 是否说明空值、缺失值、异常状态。

## 4. DSP 影响

- [ ] 是否影响 RTD Reason。
- [ ] 是否影响 Sorting。
- [ ] 是否影响 Dispatch / Where Next。
- [ ] 是否影响 AMA 触发或动作。
- [ ] 是否影响 MES 状态。
- [ ] 是否影响 MCS / AMHS 搬送。
- [ ] 是否影响 EAP / 机台状态。

## 5. Report / UI / DB

- [ ] 是否新增或修改 Report。
- [ ] Report 唯一维度是否明确。
- [ ] Report 字段说明是否完整。
- [ ] Report 生成频率是否明确。
- [ ] 是否需要新增 UI 配置。
- [ ] UI 字段是否说明必填 / 非必填 / 默认值。
- [ ] 是否需要 DB 新增字段或表。

## 6. 测试可行性

- [ ] Normal Case 可写。
- [ ] Boundary Case 可写。
- [ ] Exception Case 可写。
- [ ] Recovery Case 可写。
- [ ] Regression Case 可写。
- [ ] 每个输出字段都有验证方式。

## 7. 典型高风险点

- [ ] Priority Lot 是否单独计算或单独排序。
- [ ] qsort / Timeline / QTime 边界是否清楚。
- [ ] PM 时间是否重复累计。
- [ ] WPH / UPH 取不到时如何处理。
- [ ] Lot 无可作业机台时如何处理。
- [ ] 两厂平均逻辑是否与单厂逻辑边界清楚。
